# Meditate 机制优化方案

## 一、修改目的

### 1.1 当前问题

当前 Meditate（每日反思）机制存在一个**逻辑漏洞**，导致知识外置功能几乎无法正常工作：

| 步骤 | 当前实现 | 问题 |
|------|----------|------|
| 收集对话 | 从数据库读取完整消息 | ✅ 正常 |
| 构建输入 | **每条消息截取前 500 字符** | ❌ 信息丢失 |
| LLM 分析 | 基于截断内容提取 | ❌ 只能看到碎片 |
| 知识外置 | 期望输出超过 2000 字符 | ❌ 不合理 |

**结果**：输入被截断后，LLM 看不到完整内容，自然无法识别出超过 2000 字的长知识，知识外置功能形同虚设。

---

## 二、需要解决的问题

### 2.1 核心问题：输入截断导致知识识别失败

```
当前流程：
用户完整对话（可能几千字）
        ↓
每条截取 500 字符  ← 信息在这里丢失了！
        ↓
LLM 只能看到碎片
        ↓
LLM 输出的 long_content 最多也几百字
        ↓
永远达不到 2000 字符阈值
        ↓
知识外置永远不会触发
```

### 2.2 次要问题：无效内容干扰

- AI 回复中失败的内容（"无法做到"、"不支持"）
- 无效的尝试、报错信息
- 纯粹的寒喧客套

这些内容会占用 LLM 的分析窗口，降低提取质量。

---

## 三、解决方案

### 3.1 核心思路

> **不截断输入，让 LLM 过滤；完整内容中提炼知识**

1. **不过滤输入**：直接传递完整对话内容给 LLM
2. **LLM 过滤**：通过 prompt 让 LLM 自动过滤无效内容
3. **完整提炼**：LLM 从完整对话中识别需要外置的长知识

### 3.2 具体修改点

#### 修改点 1：取消消息截断

```python
# 当前代码（有bug）
if len(content) > 500:
    content = content[:500] + "..."  # ← 截断！

# 修改为
if len(content) > 3000:  # 放宽到 3000，或直接不限制
    content = content[:3000]  # 或完全不做截断
```

#### 修改点 2：添加字符数上限保护

虽然不截断，但需要防止输入过长：

```python
max_input_chars = 50000  # 限制总输入约 50000 字符

# 累积添加，超过则停止
if total_chars + len(content) > max_input_chars:
    break  # 不再添加更多内容
```

#### 修改点 3：优化 LLM 提示词

明确告诉 LLM：
1. 过滤规则（哪些要忽略）
2. 提取规则（哪些要保留）
3. 输出格式（特别是 long_content 的条件）

#### 修改点 4：增加 summary 字段

让 LLM 先总结今日对话全貌，便于后续参考。

## 四、修改后的流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    优化后的 Meditate 流程                           │
└─────────────────────────────────────────────────────────────────────┘

1. 收集昨日对话
   └── 从 messages 表读取，不截断
       ↓
2. 构建输入（优化版）
   └── 直接拼接所有消息
   └── 设置 50000 字符上限（防止超限）
   └── 添加元信息提示任务
       ↓
3. 调用 LLM 分析（优化提示词）
   └── 明确过滤规则：忽略 AI 失败/无效回复
   └── 明确提取规则：保留有效知识
   └── 要求输出 summary + 4 类知识
       ↓
4. 知识外置判断
   └── 检查 details/long_content 是否 ≥ 2000 字符
   └── 超过阈值 → 写入 knowledge/ 目录
   └── MEMORY.md 只保留摘要 + 引用
       ↓
5. 合并到 MEMORY.md
   └── operations → 操作记录
   └── knowledge → 知识库
   └── notes → 重要备忘
   └── long_content → 知识文件引用
```

## 五、LLM 提示词设计

### 5.1 分析提示词（完整版）

```python
analysis_prompt = """你是一个记忆分析助手。你的任务是从对话记录中提取需要长期保存的重要知识。

## 重要提示
1. **过滤无效内容**：忽略以下内容
   - AI 回复中失败、报错、无法执行的内容
   - AI 说"无法做到"、"不支持"、"没有权限"等拒绝性回复
   - 纯粹的寒喧、客套、确认信息
   
2. **保留有效知识**：从以下内容中提取
   - 用户提供的项目信息、技术方案、决策
   - AI 成功给出的建议、解决方案
   - 可以复用的操作步骤
   - 值得记住的知识点

3. **长知识外置**：如果知识内容特别详细（超过2000字），必须放到 long_content 中

## 对话记录

本对话记录来自 {session_count} 个会话，共 {char_count} 字符。
你的任务是过滤无效内容后，提取有用知识。

{all_content}

## 输出格式（JSON）

只返回 JSON 格式，不要其他内容。

{{
    "summary": "今日对话的简短总结（不超过100字）",
    "operations": [
        {{"title": "操作名称", "steps": ["步骤1", "步骤2"], "context": "应用场景"}}
    ],
    "knowledge": [
        {{"topic": "知识点主题", "summary": "核心要点（不超过100字）", "details": "完整知识说明"}}
    ],
    "notes": [
        {{"content": "备忘内容", "priority": "high/medium/low"}}
    ],
    "long_content": [
        {{"title": "主题", "content": "超过2000字的详细内容，需要单独存文件"}}
    ],
    "ignored_count": "忽略的消息数",
    "kept_count": "保留的消息数"
}}
"""
```

## 八、预期效果

| 场景 | 修改前 | 修改后 |
|------|--------|--------|

## 九、风险与注意事项

1. **输入长度限制**：如果对话特别多，可能超过 LLM 上下文窗口
   - 解决：设置 50000 字符上限，超出则截断最后几条

2. **成本考虑**：完整内容会增加 token 消耗
   - 解决：Meditate 是低频任务（每天一次），成本可接受

3. **LLM 过滤准确性**：依赖 prompt 效果
   - 解决：可在实际使用中根据效果调整提示词
